# Agent Note: 将受审批约束的工具审查做成策略驱动的应答者

Status: implemented

[English](2026-08-24-auto-review.md) | 中文

## 问题

审批 seam 通过一个与通道无关的应答者来授权或拒绝工具请求，但应答者本身对"这个请求是否安全"并没有产品层面的判断。一个想在破坏性或凭据相关的命令之前获得第二意见的部署，要么手写一个 `approval/request` 监听器，要么干脆不做审查。直接把审查者塞进审批服务，会把一个中立的 seam 耦合到单一的审查策略上。

## 决定

新增一个独立的 `@deepseek-ai/dsh-auto-review` 函数插件，以 `approval/request` 应答者的方式前置注册。当 `enabled` 开启时，它先对请求的威胁类别进行分类，再让一个专门的审查子代理返回结构化判定，套用配置好的 `ReviewPolicy`，并把结果映射成 `ApprovalOutcome`。强制执行仍由审批服务负责：auto-review 只决定一个本已合格请求的结果，无法把 `'never'` 策略变成交互式提示。

### 审查子代理

审查者通过标准子代理 seam（`ctx.subagents.start`）作为一个受限子代理运行。它接收工具名、原因以及分类出的威胁类别，被约束为自身不持有任何工具（`toolFilter: { allow: [] }`），并返回结构化 `ReviewOutcome`（`{ risk, decision, reason? }`）。如果子代理未能完成并给出结构化判定，应答者就会通过委托给下一个监听器而以拒绝方式关闭。由于进程内驱动是在应用过滤器之后才挂载结构化输出工具，因此空工具过滤器不会把该工具也过滤掉。

### 策略映射

`ReviewPolicy` 包含 `rules` 列表与 `noMatch` 兜底。每条规则命名一组 `categories`、一个 `minRisk` 下限，以及 `allow` 或 `deny` 的 `decision`。`decide()` 按顺序将分类出的类别与审查者的风险分级同每条规则比较；第一条匹配的规则给出最终判定，无匹配时回退到 `noMatch`。`allow` 判定映射为 `allowed-once`，`deny` 映射为 `rejected`，其余情况（包括 `defer` 或 `noMatch: 'defer'`）则委托给下一个应答者。`Reviewer` 是可替换的 seam，因此策略逻辑可以独立于子代理传输进行单元测试。

### 审计轨迹

每次审查都会追加一条只写日志的 `approval/review` 会话事件，记录最终的 `risk`、`decision` 与判定结论，与既有的 `approval/asked`/`approval/decided` 审计事件保持一致。配套的运行时不变量（`@deepseek-ai/dsh-auto-review/invariant`）会校验这些记录只携带已知分级，从而让异常的审查记录无法悄悄污染持久化日志。

## 考虑过的备选方案

**把审查放进审批服务内部。** 这会把一个中立的、与通道无关的 seam 耦合到单一的产品策略，并迫使服务自己管理子代理生命周期。独立的应答者让服务保持职责边界，把组合交给部署方。

**让人工成为唯一审查者。** 该 seam 已经通过其自身应答者支持这种做法。auto-review 是额外的、可选的机器审查者，并不是审批服务策略或人工应答者的替代品。

**在 `ApprovalPolicy` 联合类型里增加一种审查模式。** 扩展 `'ask'`/`'never'` 会触及所有 `assertNever` 边界，并混淆"谁有权决定"与"做出什么决定"。auto-review 完全活在应答者里，不触碰该联合类型。

## 验证

包测试覆盖了纯函数 `classify` 与 `decide`、应答者的关闭/委托/允许/拒绝/抛出路径、不变量的接受与拒绝用例，以及一个真实组合测试：在同一个上下文中挂载 agent 循环、进程内 spawn 子代理提供者与本插件，用一个脚本化的 mock 模型驱动审查子代理返回结构化判定。还有一个销毁测试证明：当插件 fiber 被销毁时，`approval/request` 监听器会被移除（HMR 安全）。源码达到 100% 覆盖率。

## 后果

想要第二意见的部署只需开启插件并配置策略；不需要的部署不受影响，因为审查默认关闭。审查者的 token 消耗在子会话中，对父上下文不可见。审查者的风险分级并未针对专门的威胁模型做过校准；严重程度校准与按会话/可学习策略留待后续工作。强制执行权仍在审批服务手中，因此 auto-review 收窄了它被允许做出的决定，而不是扩大服务的权限。
