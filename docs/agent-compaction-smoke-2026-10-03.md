## 已复现的源码问题与修复

1. `/compact` 经过普通聊天的工作区上下文、意图指导、Skill 或计划模式拼装，原生命令语法可能被破坏。现在仅独立 `/compact` 走命令路径，不执行这些任务准备；多行 Skill 调用与普通任务仍走原路径。
2. 原生压缩没有普通聊天的 `turn/end`。此前桥接等待该事件，空历史命令也一直不结束。现在由命令 RPC 的成功/失败确认收尾，不制造额外聊天轮次，支持停止和错误释放状态。
3. 真实长历史测试在 30 秒时失败：本机 API 客户端给命令维护套用了短 unary 请求的默认超时。新增 `commandOnly` 请求语义：未找到原生处理器就明确拒绝，不回退模型；该类维护只采用调用方/连接取消，不套用 30 秒健康检查截止。普通短 RPC 保持原超时。原生 Stop 仍可取消摘要生成，没有设置整轮任务硬时限。
4. mux 事件与 RPC 响应独立到达，摘要用量可能尚未交付。桥接优先使用本轮 `compaction/summary` 用量；缺失时查询持久化历史尾部，只接受当前维护开始后产生的摘要，不借用旧摘要用量。可选统计失败不把已经成功的维护变成失败。

## 确定性验收（真实 Host，本机受控模型）

`npm run test:z-host-deploy` 通过：

- 生产 IPC handler 闭包测试：选择 goal 模式和 Skill 时，`/compact` 仍原样发给原生 Host，不执行快照、上下文拼装、Skill 注入或编排。此用例替换协作者，不是 Electron 传输/渲染测试。
- 空历史压缩立即返回，无模型请求、无残留 busy。
- 压缩落地 checkpoint，原始持久化日志前缀逐事件不变；后续请求使用 checkpoint，最末条消息仍原文保留。
- 摘要输入/输出用量准确返回。
- 非法参数报错并释放状态。
- 受控摘要延迟 31 秒，实际部署客户端成功返回，不再被 30 秒截止切断。
- 压缩中停止：生成被取消，未落地摘要，保留原历史并释放 busy。
- 不支持 `/compact` 的只读预设明确拒绝，不发给模型。
- 原生 MCP、只读模型工具、并发 DAG、重启后历史恢复和排队生命周期回归通过。

另有原生 API 模型/Schema/传输/取消 119 个测试通过，原生手动压缩/命令 42 个测试通过；生产 hook、流缓冲、聊天桥接、持久化、运行时解析与生产构建通过。

## 真实供应商样本与限制

当前模型 `xiaomi/mimo-v2.5-pro`。归档有 49,413 个事件、28 轮、132 次工具调用。原归档 SHA-256、大小和修改时间前后不变。

首次 `--run --compact`：短问题、旧历史短问题、热缓存重复、测试事实种植与尾部分隔均通过；原生压缩在约 30 秒时因客户端超时失败。报告：临时目录 `taskweaver-history-smoke-KhpWrE/report.json`。

修复后的第一次全量实测：

| 用例 | 耗时 | 结果 |
| --- | ---: | --- |
| 新会话简单问题 | 6.7 秒 | 正确，无工具 |
| 旧长历史简单问题 | 21.7 秒 | 正确，无工具 |
| 同一旧历史热缓存重复 | 6.4 秒 | 正确，无工具 |
| 原生压缩旧历史 | 79.4 秒 | 成功替换 293 个历史条目，保留原日志，用量返回 |
| 压缩后测试事实回忆 | 5.0 秒 | 未通过精确验证码断言 |

报告：临时目录 `taskweaver-history-smoke-ShmYlm/report.json`。该轮初版测试只检查整个 summary 事件是否包含验证码，事件也含原始模型输出（可能含思考），不能据此证明验证码进入有效 checkpoint。已加强测试：分别核验纯摘要、真正落地的替换消息、被替换源消息与后续精确回忆；失败保留用量及合成标记匹配指标，不打印用户历史正文。

因此当前只证明链路不再被 30 秒超时截断，不能把压缩成功等同于事实保留可靠，也不能宣称长任务延迟已全部解决。原历史用量、原生 token-meter 估计的压缩规模与供应商上报输入并非同一种计数，不应直接混算。

加强后的再次实测（`taskweaver-history-smoke-wCCEUR/report.json`）：未先问简单问题的旧 fork 在事实种植用例耗时 64.4 秒，输出包含新种植的合成验证码，但未按要求只回答 `FACT_SAVED`，前置断言失败。随后供应商返回 HTTP 402 `Insufficient account balance`，摘要请求也未成功；已停止真实模型实验，不自动换模型或继续付费请求。该轮无法证明摘要事实保留成功。测试脚本已经补上前置失败短路：一个用例失败后不再执行后续问题，事实种植/尾部分隔失败后也不再发起摘要与回忆请求，避免无效重复费用。

上述三次测试均验证原归档字节、大小、修改时间不变；测试配置、凭据和会话副本已删除，只保留聚合报告。原始记录未被压缩或清空。
