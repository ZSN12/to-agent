## 0. 总览与方法

- **排序原则**：收益 ÷ 工作量（ROI）。Wave 1 全部是"高收益 × 小工作量"的快速胜利；Wave 2 是结构化改造；Wave 3 质量优化，其中部分可作论文素材。
- **验证原则**：每波次改动前后必须跑仓库现成基准对比，不靠感觉。现成设施：
  - `scripts/diagnose/tw-bench.mjs` — 每轮 RPC 往返实测（首字延迟）
  - `scripts/benchmark-dag-performance.mjs` — DAG 拓扑/调度/执行三场景基准（small→xlarge）
  - `scripts/perf-gate.mjs` — 启动性能硬门槛（首屏 <1000ms 等）
  - `backend/orchestration/performance-monitor.mjs` — `TASKWEAVER_PERF_MONITOR=1` 全局采样 P50/P95/P99（2026-10-29 已删除：从未接入生产代码）
  - 包内 Vitest —— 行为改动必须补/更新针对性测试
- **流程约束**（来自 AGENTS.md）：批量或高风险改动前创建独立 Git 检查点（隔离索引，不动用户原有暂存状态）；涉及序列化/文件路径/IPC 的改动必须覆盖失败与边界输入。
