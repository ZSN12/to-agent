# TaskWeaver 系统架构文档

本文档为 TaskWeaver 智能多智能体研发辅助平台的核心技术架构文档，主要阐述系统的分层架构、通信机制、核心模块、安全隔离模型以及多智能体协作与调度机制。本文档作为毕业设计论文第 3~4 章核心技术架构参考材料。

## 1. 系统整体进程模型
TaskWeaver 采用标准的三层架构体系，将 UI 表现与核心业务逻辑进行了严格隔离：
- **Electron 主进程（Main Process）**：负责应用生命周期管理、原生系统接口调用、窗口管理。
- **渲染进程（Renderer Process）**：基于现代前端框架构建用户界面，负责与用户进行交互、呈现 Agent 的规划与执行过程。
- **Host 运行时（Host Runtime）**：业务核心引擎。负责执行多智能体调度、沙箱命令执行、文件系统操作及模型接口调用。此层通过独立子进程或线程与主进程隔离，确保核心逻辑不受 UI 线程阻塞。
三者之间通过严格定义的 IPC 机制进行通信。

## 2. 运行时组合机制
核心 Host 运行时的装配通过 **Cordis 微内核** 机制实现高度解耦：
- **Cordis 微内核**：提供生命周期管理、依赖注入和上下文隔离。
- **Plugin 插件化装配**：所有的能力（如文件操作、终端沙箱、大模型桥接）均以独立 Plugin 形式注册到运行时上下文中，使得整个系统模块可热插拔。
- **运行时 Profiles 与 Presets**：支持基于预设（Presets）与配置文件（Profiles）定义运行时的加载行为，根据不同环境（如开发测试、生产环境、特定研发任务）装配不同的底层 Plugin。

## 3. 核心包族划分
系统采用 Monorepo 结构，将业务域划分为一系列高内聚的核心包：
- **core**：系统基石，包含微内核及核心生命周期、接口定义。
- **fs**：统一文件系统操作，封装跨平台差异及文件沙箱隔离能力。
- **shell**：命令终端支持，负责生成带 Seatbelt 的安全执行上下文。
- **subagent**：子 Agent 的基础能力支持、角色定义与通信。
- **session**：管理用户会话、对话状态、上下文历史以及持久化。
- **orchestration**：负责任务编排、拓扑构建与生命周期调度。
- **provider-bridge**：统一网关协议，用于桥接不同的大模型供应商接口。

## 4. IPC 架构与契约安全
基于进程间通信安全至上的原则：
- **单一接口表 `channels.mjs`**：所有暴露给渲染层的跨进程接口必须在统一的接口契约表中定义，避免隐式通信漏洞。
- **Preload 隔离通道**：渲染进程无法直接访问 Node.js API，必须通过 preload 脚本按通道契约转发调用，严格执行 Context Isolation。
- **backend:ready 握手**：Host 运行时与渲染端通过标准的就绪握手事件建立连接，确保在安全连接确立前，系统处于安全静默状态。

## 5. 安全与沙箱模型
系统为 Agent 提供受限但高效的执行环境：
- **Seatbelt 沙箱与精确命令白名单**：基于 Seatbelt 技术，只允许 Agent 运行在经过严格筛选的白名单命令集合内，杜绝危险的高权限操作。
- **资源隔离**：
  - **只读范围 `scopePaths`**：限定 Agent 仅能读取被授权的工作区数据及配置。
  - **写隔离 `writeScopes`**：Agent 的任何代码生成或文件修改动作必须落在指定的可写域内。
- **Worktree 安全隔离与 Git Checkpoint**：当涉及具有破坏性或高风险的代码变更时，系统会在隔离的 Git Worktree 中执行，结合 Git Checkpoint 快照技术，确保每次重构均具备安全的回滚机制。

## 6. 多智能体协作与 DAG 拓扑编排
系统支持多 Agent 异步并行的复杂研发流：
- **Kahn 调度机制**：利用 Kahn 算法对任务 DAG (有向无环图) 进行拓扑排序，确保具有前置依赖的子任务按照正确的执行顺序被调度给对应 Agent。
- **Evidence 证据验收**：每个子任务节点执行完毕后，不仅输出结果，还必须提供可验证的 `evidence`（如执行日志、测试结果等），供后续 Agent 或上级评估节点验收。
- **用量账本与预算门禁**：对模型 Token 消耗及资源开销进行全流程打点追踪，实施预算熔断与限流机制，避免不可控的资源耗尽。
