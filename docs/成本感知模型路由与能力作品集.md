## 1. 动机与原则

TaskWeaver 的编排目标仍是：

> 在质量约束下，最小化**成功完成一次任务**的预期总成本（含重试、升级、协调开销），而不是单次 API 报价最低。

用户侧往往同时持有多种**计费形态**：

| 形态 | 典型例子 | 路由含义 |
|------|----------|----------|
| 按量计费 | 官方 API、部分中转 | 用 `input_price` / `output_price` 估算边际成本 |
| 订阅／打包 | Cursor、Codex、反重力（Antigravity）等桌面客户端 | 订阅覆盖内没有单次 API 账单，但账号额度仍可能稀缺；按任务适配和额度周期决定是否倾向使用 |
| 时段差异 | DeepSeek 官方工作日白天加价等 | 在「贵时段」对按量模型降权或换通道 |

因此，分配器不能仅靠 UI 上的「低／中／高」三档或固定 `tier` 排序；需要一份用户可维护的**能力作品集（Routing Portfolio）**，把「任务适合谁」「当前哪条通道更划算」写清楚，再由规则打分产出可解释的 `routeReason`。

**与门控的关系（不变）**：入口 `RuleGate` 仍**不调用**任何 LLM；作品集与成本打分仅用于：

- 多智能体路径上的 **子任务分配**（`AllocationRouter` / `selectModelForTask`）；
- 可选：单 Agent 下用户未手动锁模时的**默认执行模型**（产品开关，非论文必需）。

## 2. 界面：模型只展示「名字」，通道进设置

### 2.1 主界面（对话、Composer、DAG 节点摘要）

- **只展示**用户可读的 **displayName**（如「Gemini 3.8 Flash」「Composer 2.5」「DeepSeek V3.2」）。
- **不展示**提供方通道标签（官方 API、OpenCodex、`cursor/`、`google-antigravity/` 等）——避免用户每次选模型时做「渠道经济学」。
- 当前实际使用的 `model_id` 可在「会话详情 / 轨迹」中展开查看，供调试与论文截图。

### 2.2 设置（模型管理）

- **已添加模型**：扁平列表（用户显式添加的条目），**取消**列表上的「低／中／高」质量档展示。
- **通道与凭据**：在「高级」或按提供方折叠的区域配置（API Key、本机 `ocx`、OAuth 说明等）；同一逻辑能力若有多通道，在设置里并列，主界面仍是一个 displayName 或用户自选默认通道。
- **参与自动分配**：保留 `enabledForAllocation`（或等价开关），让用户声明「这条模型允许编排器选用」。

### 2.3 与现有实现的关系

- 今日 UI 仍从 `profile.tier` 或成本推断渲染「低／中／高」（`src/features/models/format.ts`）——属**待移除**的产品债。
- `ModelProfile.tier` 在数据层可保留为**内部分档**（PolicyGate、冷启动先验），但**不对用户暴露三档文案**。

## 3. 能力作品集（Routing Portfolio）

作品集是用户（或仓库默认模板）维护的 **YAML/JSON**，与 `pricing/registry.json`（自动价签）**互补**：

| 数据源 | 职责 |
|--------|------|
| `pricing/registry.json` + adapters | 按量单价、上下文窗口、同步审计（见《模型价签自动同步》） |
| **routing-portfolio**（建议路径：`config/routing-portfolio.yaml`） | 订阅偏好、通道策略、任务—模型亲和、时段规则、displayName 映射 |

### 3.1 建议结构（示意）

```yaml
version: 1
display_names:
  "google-antigravity/gemini-3.8-flash-medium": "Gemini 3.8 Flash"
  "cursor/composer-2.5": "Composer 2.5"

subscriptions:
  - id: antigravity_pack
    label: 反重力订阅
    note: 约 20 元 / 18 个月，覆盖 Google Antigravity 通道模型
    prefer_models:
      - "google-antigravity/*"
    marginal_cost: 0

  - id: cursor_codex
    label: Cursor / Codex 订阅
    prefer_models:
      - "cursor/composer-2.5"
      - "cursor/grok-4.6"
    deprioritize_models:
      - "cursor/gpt-6*"   # 极少使用，除非任务强制 strong + PolicyGate
    marginal_cost: 0

metered_surge:
  - provider: deepseek
    timezone: Asia/Shanghai
    windows:
      - days: [mon, tue, wed, thu, fri]
        hours: [9, 18]
        surcharge_factor: 1.5
    action: deprioritize   # 或 route_to_alternate: deepseek_via_ocx

task_affinity:
  research:
    prefer: [cheap_search, subscription_gemini_flash]
    avoid: [strong_only]
  review:
    prefer: [strong_reasoning]
    min_capability: security_review
  implementation:
    prefer: [balanced_code, xiaomi_v26]   # 示例：写代码偏好
  hard_debug:
    prefer: [gemini_pro_class, strong_reasoning]

capabilities:
  xiaomi_v26:
    match_model_ids: ["*/mimo-v2.6*", "*/xiaomi*"]
    tags: [balanced_code, zh_copywriting]
  cheap_search:
    match_tier: cheap
    tags: [research]

quota_cycles:
  enabled: true
  source: openusage-local-api       # optional; manual entry is also supported
  base_url: http://127.0.0.1:6736
  schema: openusage.limits.v1
  max_snapshot_age: use_source_expiry # honor expiresAt/stale; don't invent missing limits
  policies:
    - provider_id: codex
      resource_id: weekly
      rollover: false                # enable only if verified for this exact plan
      use_before_reset: true
    - provider_id: cursor
      resource_id: totalUsage
      rollover: unknown              # unknown means no urgency bonus
      use_before_reset: false
```

`match_model_ids` / `tags` 与 `ModelProfile`、价签合并后，由分配器解析为候选集合。

### 3.2 用户可编辑性

- 毕设演示：**仓库自带默认 portfolio** + 设置页「导出／编辑作品集」（可选）。
- 论文表述：作品集体现「用户对自己账号经济学与能力偏好的建模」，比黑盒三档更符合「可解释路由」。

## 4. 路由打分：像人一样选模型

### 4.1 输入

- `TaskSpec`（类型、风险标签、`acceptance`、是否只读等）；
- 用户**已添加**且 `enabledForAllocation` 的 `ModelProfile[]`；
- 合并价签后的 **边际成本**（订阅内 → 0；按量 → registry； surge → 加权）；
- 作品集：`task_affinity`、`subscriptions`、`metered_surge`、`quota_cycles`；
- 可选 `UsageSource` 的额度快照（原始单位、剩余值、重置时间、`fetchedAt`/`expiresAt`、`stale`、错误）；
- 可选：`historical_success`（审计日志回填）。

### OpenUsage 作为可选 UsageSource

已检查 GitHub 项目 [`robinebers/openusage`](https://github.com/robinebers/openusage)：它是独立的 macOS 菜单栏用量查看器，提供本地只读 `GET http://127.0.0.1:6736/v1/limits`，响应 schema 为 `openusage.limits.v1`，按 provider/resource 提供原始单位、已用/上限/剩余量、重置时间、`fetchedAt`/`expiresAt`、`stale` 和 errors。仓库 README 当前列出 Codex、Cursor、Antigravity、Claude、Copilot、OpenCode、OpenRouter、Z.ai 等支持项；具体字段依各服务可提供的数据而异。TaskWeaver 可用小型适配器消费该接口，不需要复制其 Provider 凭据读取逻辑。参照其 [README](https://github.com/robinebers/openusage) 与 [Local HTTP API 文档](https://github.com/robinebers/openusage/blob/main/docs/local-http-api.md)。

- OpenUsage 不安装/未运行时，TaskWeaver 仍可正常工作；额度回退为 `unknown`，继续按能力、价格与用户 Portfolio 路由。
- 尊重 `stale`、`expiresAt`、`fetchedAt` 和 errors。保留的最后成功快照可供设置页查看，但过期值不得参与额度加权。
- Provider 资源不一定一一对应 TaskWeaver 的 `model_id` 或账号，且可能代表共享池；只按明确配置的 `provider_id + resource_id + route mapping` 关联，禁止推断成模型级精确余额。
- API 只监听 loopback、仅提供 GET/OPTIONS，但允许浏览器跨域读取用量数值；TaskWeaver 应由 Electron 主进程访问固定地址、校验 schema 与响应大小，并确保用量快照不进入远程遥测。
- 额度来源表达消费状态，不提供模型能力真值；工具兼容性与能力仍由 ModelProfile/运行时验证。

### 4.2 硬约束（PolicyGate，先于打分）

与设计方案 §7.4 一致，例如：

- `security` / `auth` 等标签 → 禁止 `cheap` 直接写入；
- 无自动验收的写任务 → 需要 Reviewer 节点或更强执行档；
- 不支持 tools 的模型 → 不能担任带工具的 executor。

### 4.3 软打分（RuleRouter v1）

对每个可行候选计算标量分（越高越优），并生成**人类可读** `reasons[]`：

```text
score =
  w_task   * task_affinity_match(task, model, portfolio)
+ w_sub    * subscription_bonus(model)          # 订阅内 marginal_cost = 0
+ w_quota  * quota_cycle_bonus(route, snapshot)  # fresh, comparable, non-rollover quota only
- w_meter  * metered_cost_estimate(task, model, now)
+ w_hist   * historical_success[task.type]
- w_risk   * underpower_penalty(task.risk, model.tier)
```

额度周期加分必须在 `PolicyGate` 和能力过滤之后计算。只有快照新鲜、单位/额度窗口明确、`remaining` 和 `resetsAt` 可用，并且该套餐确认不可结转时，才计算“刷新前可利用额度”偏好：剩余比例较高且距离刷新较近时有限加分。额度临近耗尽、可结转、刷新语义未知、快照过期或字段缺失时不加分。它是**软偏好**：不为消耗额度制造额外请求，也不改变任务质量门槛或替用户设置任务预算。

```text
quota_cycle_bonus = 0  if stale/unknown/unit-incomparable
quota_cycle_bonus = 0  if rollover != false
otherwise bounded(urgency(time_to_reset) * remaining_ratio * task_route_eligibility)
```

`task_route_eligibility` 只表示任务在能力与安全约束下适合该路线，不允许把不合格模型加回候选集合。毕设演示使用可复现的固定规则，不拟合复杂预测器。

**示例策略（与产品讨论一致）**：

| 场景 | 倾向 | 理由文案示例 |
|------|------|----------------|
| 仓库内搜索、读文件归纳 | 便宜按量或订阅内 Flash | 「检索型子任务，优先低成本」 |
| Code Review / 安全 | 强推理（如 GPT-5.x 档） | 「验收含 review，抬升推理档」 |
| 中文文案、说明性写作 | 用户标注的写稿模型（如小米 V2.6） | 「任务亲和：balanced_code」 |
| 难解 bug、跨模块 | Gemini 类长上下文／强推理 | 「hard_debug 亲和」 |
| 反重力订阅有效 | `google-antigravity/*` 优先 | 「订阅边际成本为 0」 |
| Codex 订阅有效 | 常用 Composer 2.5、Grok 4.6 | 「订阅默认通道」；GPT-6 仅强约束下 |
| 订阅额度临近刷新且确认不可结转 | 仅对任务适配的模型增加有限偏好 | 「额度快照显示刷新将近且剩余较多；只作为软偏好」 |
| DeepSeek 官方贵时段 | 降权或走备用通道 | 「工作日白天按量加价，已降权」 |

输出与 §5.4 `RouteDecision` 对齐：`model_id`、`strategy`、`reasons`、`fallback`、`confidence`（可由分差归一化）。

### 4.4 与「三档」的替代关系

| 旧思路 | 新思路 |
|--------|--------|
| UI 低／中／高 | 用户只看 displayName；档位仅内部元数据 |
| `TASK_TIER_ORDER` 固定映射 | `task_affinity` + 打分 + PolicyGate |
| 仅 `costPerMillion` 排序 | `marginal_cost`（订阅 0 + surge + 按量） |

实现落点：`electron/backend/orchestration-policy.mjs` 的 `selectModelForTask` 由 tier 排序演进为 **portfolio 感知打分**；价签仍来自 `electron/backend/price-registry.mjs`。

## 5. 单 Agent 与多 Agent 的统一叙事

- **单 Agent**：用户手动选的模型优先；若开启「智能默认」，则用**同一套打分**选主执行模型（不增加 Planner 成本）。
- **多 Agent**：Planner 只产出 `TaskSpec[]`；每个节点独立 `RouteDecision`，从而在一条 DAG 上呈现「搜索用便宜、审查用强、实现用写代码偏好」的**异构路由**，便于论文案例与 Trajectory 展示。

## 7. 论文与演示建议

- **案例 A**：同一需求「全链路强模型」vs「动态分配」——对比 Trajectory 中的 `model_id` 与估算 token 成本（各 1 次即可）。
- **案例 B**：显式展示反重力/Codex 订阅偏好——修改 portfolio 前后 `reasons` 变化。
- **案例 C**：DeepSeek 贵时段——改系统时间或 mock `now` 展示降权。

**诚实局限**：订阅覆盖与是否结转可能以用户配置或服务方展示为准；OpenUsage 支持面、API 可用性和资源粒度受其版本及各提供商接口限制；`ocx` 目录漂移需重新同步；路由不保证等价于各客户端内手动点选的最优，只保证**可复现、可解释**。
