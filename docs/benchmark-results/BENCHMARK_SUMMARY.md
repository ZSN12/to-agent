# TaskWeaver 算法性能优化对比报告（毕业设计支撑数据）

生成日期：2026-10-30
测试硬件：Apple M4 Pro (12 核), Node.js v22.23.1, pnpm 11.7.0

所有耗时来自本机合成负载。原始样本、提交、源码哈希、预热/采样口径和运行命令保存在对应 JSON 中；不将微基准解释为生产 p95。

## 1. Markdown 流式解析性能对比 (A02)

| 输入规模 | 原始算法 p50 / p95 (ms) | 优化算法 p50 / p95 (ms) | p50 加速比 |
|:---|:---|:---|:---|
| **1,000 行** | 35.84 / 37.42 | 0.638 / 1.36 | **56.2x** |
| **2,000 行** | 198.40 / 315.68 | 1.40 / 1.76 | **141.8x** |
| **4,000 行** | 618.50 / 664.99 | 2.44 / 3.09 | **253.3x** |
| **8,000 行** | 2552.85 / 2754.92 | 1.75 / 2.11 | **1455.1x** |

旧实现对已读前缀反复执行 `slice/split/map`；当前实现用状态扫描并只处理新增文本。基准以当前源码 SHA 与保留的旧实现 fixture 分别运行，详见 [Markdown benchmark JSON](markdown-stream-2026-10-29.json)。

## 2. 语义搜索 Top-K 堆选择性能对比 (A01)

| 向量数 | 全量排序 p50 / p95 (ms) | MinHeap p50 / p95 (ms) | p50 加速比 | 候选项工作集 |
|:---|:---|:---|:---|:---|
| **1,000** | 0.157 / 0.257 | 0.112 / 0.183 | **1.40x** | 1,000 → 30 |
| **5,000** | 0.890 / 1.02 | 0.834 / 0.944 | **1.07x** | 5,000 → 30 |
| **10,000** | 2.00 / 2.62 | 1.80 / 1.93 | **1.12x** | 10,000 → 30 |
| **25,000** | 5.64 / 7.13 | 4.43 / 5.20 | **1.27x** | 25,000 → 30 |
| **50,000** | 13.92 / 15.99 | 10.43 / 12.01 | **1.33x** | 50,000 → 30 |

使用固定种子的 64 维合成向量、Top‑30，预热 5 次、采样 20 次。两种实现的 Top‑K 顺序与分数逐项一致。堆实现仍扫描并评分整个语料；这里只报告选择阶段候选项数量（N → K），没有测量进程总堆/RSS。小语料收益接近噪声区间，较大语料改善更明显。过滤漏召回由独立源码回归验证。原始数据见 [semantic Top-K JSON](semantic-topk-2026-10-30.json)。

## 3. 会话 SQLite 更新性能对比 (A13 / P6.3)

合成负载包含一个小目标会话和不同规模的归档会话。旧版完整读取、解析和写回 V1 JSON，再执行提交后重读；SQLite 使用正式 `ThreadStore.updateConversation()`，读取并写入目标正文和摘要行。每个规模预热 5 次、采样 20 次。

| 归档正文规模 | V1 JSON 更新 p50 / p95 (ms) | SQLite 更新 p50 / p95 (ms) | p50 加速比 |
|:---|:---|:---|:---|
| **1 MiB** | 3.90 / 4.74 | 0.139 / 0.201 | **28.0x** |
| **10 MiB** | 34.09 / 36.28 | 0.117 / 0.155 | **291.6x** |
| **50 MiB** | 172.66 / 177.78 | 0.108 / 0.160 | **1598.7x** |

SQLite 列表读取只访问摘要；不相关正文的读写行数由确定性回归验证为零。损坏恢复需显式执行且只保留一代前值。数据和 I/O 计数见 [ThreadStore benchmark JSON](thread-store-2026-10-30.json)。
