## 仍发现的生命周期风险

实测中，第一轮完成后发出的 `done` 没有 `continuing` 标记，随后排队的第二轮继续运行，两轮内容在原生历史中都存在。

对应源码：

- `electron/backend/dsh-chat-service.mjs:651` 在每次 turn/end 发出 `done`；`:670` 检测到待处理追问后保留运行任务。
- `src/features/app/useAppBackend.ts:463` 收到任何 `done` 就删除会话运行标记；`:471` 删除流快照，`:473` 清除当前发送状态。
- `src/features/chat/conversation-stream-buffer.ts` 将 start/done 作为瞬态快照重置边界。

因此，后端的“本轮结束”被前端用作“会话任务全部结束”，排队追问之间可能提前清除运行状态。实测事件和源码确认了这处语义不一致，但本次没有操作界面，不能直接宣称复现了用户截图里的内容消失，也不能把瞬态快照删除等同于底层历史丢失。后续修复应区分轮次结束和运行任务完成，并核验原生历史刷新，不能简单保留所有流快照造成重复回复。

本轮只添加测试与记录，未修改产品生命周期逻辑。

## 后续修复与验收（同日）

上述结果是修改前的安装版基线。后续在源码中修复了以下链路，**没有覆盖已安装应用**：

1. 后端每轮使用独立 `turnId`，完成事件明确携带 `continuing`；首轮 IPC 结果与完成事件使用同一个轮次标识。
2. 前端仅在整个 run 完成时清除运行标记；接受排队消息或首轮 IPC 延迟返回时，不清掉下一轮的输出。
3. 每轮完成内容先进入消息列表，用相同标识去重 IPC 结果；原生投影尚未追上时保留已完成答案，追上后以原生行接管。重复的相同短答案按次数匹配，不能把两轮压成一轮。
4. 保留完成消息的编排说明和用量元数据；中间完成事件保留待处理队列，但不把完成内容留在“被中断流”的恢复快照中。
