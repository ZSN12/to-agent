# TaskWeaver 模型价签自动同步（全自动）

> 版本：2026-09-24  
> 目的：为**子任务模型分配**与成本估算提供可复现、可审计的单价来源；**不由用户每两天手动查官网**，由定时任务自动拉取/校验并写回仓库或应用数据。  
> 关联：`selectModelForTask`（`orchestration-policy.mjs`）、`model-service.mjs`（pi 目录中的 `model.cost`）、`profile-store`（档位与能力，**不存单价**）。

---

## 1. 为什么要单独做价签同步

| 现状 | 问题 |
|------|------|
| 单价来自 pi `ModelRuntime` 内置目录 + `refresh` | 更新节奏跟随上游包，**国内厂商调价不会及时反映** |
| `profile-store` 只有 tier / 能力摘要 | 分配器用 `costPerMillion` 排序时，**价不准 → 路由结论不可信** |
| 论文写「成本优化」 | 需要 **价签来源、更新时间、快照** 可写在附录 |

因此增加一层 **TaskWeaver 价签注册表（Price Registry）**，与 pi 目录 **合并展示**，以 Registry 为准（或 Registry 覆盖 pi 同 key 的 cost 字段）。

---

## 2. 设计原则

1. **全自动**：默认每 48 小时至少跑一次；失败重试 + 告警，不依赖人工抄价。  
2. **可审计**：每次同步写 `synced_at`、`source_url`、`checksum`、变更 diff。  
3. **不破坏用户配置**：`profile-store` 的 tier/能力 **不被** 同步任务覆盖；仅更新 **单价与可选上下文窗口**。  
4. **优雅降级**：同步失败时 **沿用上一版快照**，UI 提示「价签已过期 N 天」。  
5. **合规**：优先 **官网公开定价页 / 开放文档 / 官方 API**；避免对抗式爬取；页面结构变了 adapter 失败应 **显式失败** 而非静默写错价。

## 3. 数据文件（建议放在仓库，开源可复用）

```text
pricing/
  registry.json              # 当前生效价签（合并结果）
  snapshots/
    2026-09-24T08-00-00Z.json
  sources/
    deepseek.json              # 各 adapter 原始解析结果（可选）
  adapters/
    README.md                  # 每个厂商对应页面 URL、解析方式、维护人
  CHANGELOG.md                 # 自动生成的调价摘要
```

### 3.1 `registry.json` 单条结构（示意）

```json
{
  "version": 1,
  "synced_at": "2026-09-24T08:00:00+08:00",
  "models": {
    "deepseek/deepseek-chat": {
      "input_per_million": 2.0,
      "output_per_million": 8.0,
      "cache_read_per_million": 0.2,
      "cache_write_per_million": null,
      "currency": "CNY",
      "source": "adapter:deepseek-official",
      "source_url": "https://…",
      "confidence": "high"
    }
  }
}
```

**model key** 与 TaskWeaver 一致：`provider/id`（与 pi 目录对齐，便于 merge）。

### 3.2 与运行时合并规则

```text
effective_cost(modelKey) =
  registry.models[modelKey] 若存在且未过期
  else pi_model.cost
```

`model-service.listCatalog()` 在序列化时注入 `costPerMillion` 与 `priceMeta: { synced_at, stale_days, source }`。

## 4. 自动化怎么跑（三种部署，可并存）

### 4.1 推荐：GitHub Actions 定时（开源仓库）

适合：**价签进 git**，用户 `git pull` 或发版 App 打包时带上最新 `registry.json`。

```yaml
# .github/workflows/sync-model-pricing.yml（实现阶段添加）
on:
  schedule:
    - cron: '0 0 */2 * *'   # 每 2 天 00:00 UTC；可改为北京时间 cron
  workflow_dispatch:

jobs:
  sync:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
      - run: npm ci && npm run pricing:sync
      - run: git diff --quiet pricing/ || (git commit -am "chore(pricing): auto sync" && git push)
```

- 脚本：`npm run pricing:sync` → `node scripts/pricing/sync-all.mjs`  
- 无变更则不 commit；有变更自动 PR 或直推 `main`（按你们分支策略）。  
- **完全不需要你每两天打开官网**。

### 4.2 桌面端：Electron 后台定时（离线用户）

在 `electron/main.cjs` 或独立 `pricing-sync-service.mjs`：

- 应用启动后 `setInterval(48h)` 调用同一套 `sync-all.mjs` 逻辑（`allowNetwork: true`）；  
- 结果写入 `userData/taskweaver/pricing-registry.json`（可与仓库 `pricing/registry.json` 合并：本地优先或远程 manifest URL）。  
- 设置页显示：上次同步时间、是否过期。

### 4.3 可选：托管 manifest（不发 git 的用户）

仓库 Actions 只更新 `https://raw.githubusercontent.com/.../pricing/registry.json`；App 每 48h **HTTP GET** 拉 manifest，校验签名或 `etag`。

## 5. Adapter 架构（国内厂商）

每个厂商一个 **adapter 模块**，统一接口：

```typescript
// scripts/pricing/types.ts（实现时用 .mjs 即可）
export type PriceAdapter = {
  id: string
  officialUrls: string[]
  fetchPrices(): Promise<Record<string, Partial<ModelPrice>>>  // key = provider/id
}
```

### 5.1 获取方式优先级

| 优先级 | 方式 | 示例 |
|--------|------|------|
| A | 官方定价 **JSON/API**（若有） | 部分云厂商 OpenAPI 价目表 |
| B | 官方文档 **稳定 HTML 表格** + 选择器解析 | DeepSeek、智谱、月之暗面、百川、MiniMax 等定价页 |
| C | pi 上游 **models 元数据** 仅作 fallback | `@earendil-works/pi-ai` 更新后 `pricing:import-pi` |
| D | 无法解析 | `confidence: low`，**不覆盖** registry 已有条目，写 CI warning |

### 5.2 国内常见来源（实现时逐个接 adapter，先 2～3 家够毕设）

| 厂商 | 建议 source_url（定价/文档） | 备注 |
|------|------------------------------|------|
| DeepSeek | 官网定价页 | 毕设 demo 常用 |
| 智谱 AI | open.bigmodel.cn 定价 | |
| 阿里云百炼 | 帮助中心模型计费 | 页面复杂，adapter 易碎 |
| 火山引擎方舟 | 文档计费说明 | |
| 月之暗面 Kimi | 开放平台定价 | |
| 腾讯混元 / 百度千帆 | 按需 | 可二期 |

**模型 id 映射表**：`pricing/adapters/deepseek.mapping.json` 把「官网模型名」映射到 `deepseek/xxx`，避免 adapter 与 pi id 不一致。

### 5.3 测试

- `npm run pricing:sync -- --dry-run`：只打印 diff，不写文件。  
- 每个 adapter 单测：用 **保存的 HTML fixture**（提交到 `pricing/fixtures/`），避免 CI 依赖外网稳定性。  
- 外网冒烟：每周一次 workflow，失败不阻断主 CI。

## 6. 与分配器、论文的关系

- **RuleRouter** 比较 `input + output` 价签时，应读 **effective_cost**（合并后）。  
- 审计日志每条子任务记录：`modelKey`、`price_snapshot_id`（registry 的 `synced_at` 或 git commit）。  
- 论文案例：「调价前后同 DAG 分配是否变化」可作为 **讨论**，不作统计结论。

## 7. 实现路线图（建议）

| 阶段 | 内容 | 工期 |
|------|------|------|
| P0 | `pricing/registry.json` 手工种子 + `mergeIntoCatalog()` in model-service | 0.5 天 |
| P1 | `scripts/pricing/sync-all.mjs` + 1 个 adapter（如 DeepSeek）+ dry-run | 1～2 天 |
| P2 | GitHub Actions 每 2 天 + CHANGELOG 自动生成 | 0.5 天 |
| P3 | 再接 2 家国内厂商 + fixture 测试 | 2～3 天 |
| P4 | Electron 48h 后台同步 + 设置页「价签状态」 | 1 天 |

毕设答辩：**P0+P1+P2** 即可声称「价签自动同步管线」；P3/P4 为开源加分。

## 8. 仍不完善、建议一并讨论的细节（清单）

与价签无关但影响「像完整产品 / 论文自洽」的缺口，建议在迭代中勾选：

| 领域 | 缺口 | 建议 |
|------|------|------|
| 外置记忆 | 设计已有 §5.6，**代码未落地** L0～L2 | 先于 Worktree 做 memory-store |
| 工作区 UI | `setWorkspace` 无设置页 | 产品补齐 P0 |
| ASK_USER 门控 | 设计方案有，实现多 binary | 补灰区确认 |
| 分配器 | 仅 tier+价排序，无 PolicyGate 硬规则 | 安全写入禁止 cheap |
| 价签 | pi 内置价可能滞后 | **本文档自动化** |
| 成功率 `p` | 期望成本公式缺历史 | 审计日志离线统计即可 |
| Explorer 角色 | 设计有，DAG 未强制 Explorer 节点 | Planner prompt 约束 |
| 并行 DAG | 调度器能力 vs worktree | 毕设可串行 |
| Codex 反代 GPT | 与 harness 差异 | 论文写 API 接入，不承诺等同 Codex |
| 价格币种 | 国内 CNY vs 国际 USD 混用 | registry 带 `currency`，比较前归一化 |

## 9. 对你问题的直接回答

> 每两天去国内 AI 官网看 API 价格，才能确保成本——希望 **自动化**，不是人工。

**赞同目标，反对人工节奏。** 正确做法是：

1. **价签与 pi 目录解耦**，用本仓库 `pricing/registry.json` + 自动 sync；  
2. **每 48 小时**由 GitHub Actions（+ 可选 App 后台）跑 `pricing:sync`；  
3. 分配与 UI **只读合并后的 effective_cost**，并展示「价签更新时间」；  
4. 官网改版由 **adapter 测试失败** 暴露，而不是你个人记得去刷网页。

实现时从 **1 个厂商 adapter + CI 定时** 做起，再扩展国内列表。
