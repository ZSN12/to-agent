## 队列问题：复现、修复与回归

`scripts/test-z-queue-lifecycle.mjs` 已加入 `npm run test:z-host-deploy`：

- 一轮运行时接受两条追问：三轮答案各自保留、三个 `turnId` 不同，`continuing` 依次为 true、true、false。
- 删除两条待处理追问：不发给模型、不进入消费后的原生历史、第一轮完成后不再 busy。
- 编辑队列中的一次输入：模型只收到编辑后的内容，没有额外轮次。
- 停止当前轮并清空追问，再发送新请求：只执行新请求，不重新唤醒已取消的旧追问。

修复前，删除用例确实失败：原生队列已空，桥接的接受计数却未减少，仍发出 `continuing=true`。现在有原生 `session/queue` 时以完整快照为准；无快照的兼容路径才使用计数回退。

停止用例随后确实失败：原生 `sessions.cancel` 保留 inbox，TaskWeaver 界面却清掉了待处理输入，之后发送新消息会唤醒旧输入。当前 Stop 在取消当前轮后等待已发起的追问 admission，再删除原生 queued/steering 项，并在停止进行期间拒绝新发送。只忽略已被消费/删除或会话已消失的具体错误，其他错误仍向上传递。未改原生 Z cancel 的通用语义。

当前四项均通过，真实部署 Host 的原生 MCP、只读工具、并发 DAG、重启历史恢复也通过。聊天桥接、生产 hook 的排队/延迟 IPC/投影接管/重复短答案/后台隔离，以及应用状态持久化回归均通过。生产 hook 验收不是浏览器或 Electron UI 端到端测试。

## 旧日志确认：慢任务不是单一原因

选择本项目映射中最大的一份归档，仅复制到隔离临时目录，用原生 cold-history API 读取聚合指标；不打印用户消息、工具内容或思考正文。归档有 49,413 个事件、28 轮、132 次工具调用。全量历史读取约 0.3 秒。

| 历史轮次 | 耗时 | 工具调用 | 思考字符 | 重试 | 观测 |
| --- | ---: | ---: | ---: | ---: | --- |
| 26 | 674 秒 | 16 | 168,883 | 0 | 持续生成/探索，约 182 秒才出现第一段 text，最后中止 |
| 12 | 497 秒 | 15 | 78,219 | 0 | 多步探索后完成 |
| 7 | 701 秒 | 0 | 560 | 2 | 两次 TIMEOUT，最大事件间隔约 300 秒，最后中止 |

第一段 text 可能是中间说明，并不等于最终答案。轮次 26 的无重试、大量 reasoning 和工具调用，不支持把它说成纯网络等待；轮次 7 的 TIMEOUT 则是另一条问题链路。归档是历史事实，不能据此断言当前配置仍使用相同超时/重试策略。

## 真实模型：同一简单问题的新旧会话对照

`scripts/run-agent-history-smoke.mjs --run` 将原归档复制到独立 home，并通过原生 fork 只继承已完成前缀。保留原工具预设，使用当前 `xiaomi/mimo-v2.5-pro` 与当前桥接。为避免旧 code 预设获得真实项目写权限，整个测试 Host 及其子进程另套 macOS 文件写入限制，只允许写测试目录；设置其临时目录也在同一边界内。

提示明确这是独立的“1+1”问题，不继续旧审查、不调用工具，最后输出校验标记。两组独立 fork 实测：

| 样本 | 场景 | 完成耗时 | 输入（非缓存 / 缓存） | 工具调用 |
| --- | --- | ---: | ---: | ---: |
| A | 新会话 | 5.8 秒 | 11,908 / 256 | 0 |
| A | 旧长会话 | 26.9 秒 | 335,805 / 9,344 | 0 |
| B | 新会话 | 9.4 秒 | 12,164 / 0 | 0 |
| B | 旧长会话首次 | 21.9 秒 | 345,149 / 0 | 0 |
| B | 同一旧会话紧接着再问 | 4.9 秒 | 151 / 345,088 | 0 |

全部回答正确，没有重新进入旧代码审查。输入字段遵循当前适配器的非缓存输入、缓存读取分开计数；旧会话总输入规模约 34.5 万 tokens，而非第二次调用只用了 151 tokens。缓存数据是供应商上报值。

这组结果表明旧历史在请求中仍占很大规模；缓存命中与响应变快一致。但小样本不能独立证明所有时延都由缓存造成，也没有复现十分钟无最终答案，不能宣称简单任务延迟已全部修复。尤其没有修改产品让简单问题丢弃历史，没有设置整轮硬时限，也没有自动压缩原会话。

## 隔离与清理

每次调用前后比较原归档 SHA-256、文件大小和修改时间，均保持不变。已核实测试复制的 settings、credentials 以及旧历史副本删除，只保留聚合报告。不会删除用户原配置或原会话。测试生成的副本可重新从原数据取得。

- 样本 A：`taskweaver-history-smoke-YGosIz/report.json`
- 样本 B：`taskweaver-history-smoke-vcaOeD/report.json`
