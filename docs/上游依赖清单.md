## 二、详细依赖分析与治理方案

### 1. OpenCodex 分叉 (`@taskweaver/opencodex`)
* **依赖形态**：Vendored 源码库，直接内置于项目代码库 `vendor/opencodex`，以 `file:vendor/opencodex` 挂载为 `@taskweaver/opencodex`。
* **上游地址**：`https://github.com/lidge-jun/opencodex`（npm 发布包为 `@bitkyc08/opencodex`，当前基线 `2.79.0`）。
* **风险评估**：上游更新频繁、破坏性重构可能打破 Cursor 适配层契约；上游官方 CLI 自更新机制可能覆盖本地源码补丁。
* **策略档位**：**B (小分叉自持)**。
* **治理手段**：
  1. **补丁范围严格锁定**：仅允许在 `src/adapters/cursor/protobuf-events.ts` 中维护极小映射（裸工具名映射至 `ocx_client_*`），由 `scripts/check-ocx-patch-scope.mjs` 守卫白名单；
  2. **禁用上游自更新**：通过 `src/lib/taskweaver-distribution.mjs` 屏蔽 `ocx update` 抓取 npm 上游包，完全由 TaskWeaver 发版统合；
  3. **上游基线追踪**：`scripts/check-ocx-upstream.mjs` 提供离线优雅降级与差异指引。

### 2. Cursor 逆向协议 (`agent_pb.ts`)
* **依赖形态**：针对 Cursor 专有 ConnectRPC / Protobuf 协议的解析与封装层。
* **上游地址**：Cursor 客户端 / ConnectRPC 端点。
* **风险评估**：**高风险**。私有协议存在随时变更、风控拦截或端点失效的可能。
* **策略档位**：**C (接口隔离+可降级)**。
* **治理手段**：
  1. **定位明确为实验通道**：系统将其严格定义为“本地可选增强/实验通道”，禁止作为核心依赖；
  2. **完全软隔离**：OpenCodex 仅作为 `127.0.0.1:10100` 的本地 HTTP 网关，主控 Agent 核心状态机、会话持久化与权限体系均在 TaskWeaver 主进程独立运转；
  3. **Wire 级契约测试**：`scripts/test-opencodex-taskweaver-patch.mjs` 构建 golden fixture 快照，确保协议微小调整均能第一时间报警。

### 3. Z 运行时 (`packages/runtime`)
* **依赖形态**：内嵌的命令执行与环境沙箱支撑层。
* **上游地址**：本地维护/自研运行时。
* **风险评估**：跨平台操作系统差异（macOS/Linux/Windows 权限与沙箱机制）。
* **策略档位**：**A (冻结内化)**。
* **治理手段**：
  1. 源码完全内置在代码仓库中，不依赖动态拉取；
  2. 构建流程通过 `scripts/build-host-runtime.mjs` 实现确定性构建与原子化产物替换；
  3. 完备的恢复历史与生命周期测试（`test:z-host`, `test:z-recovery`, `test:sandbox`）。

### 4. 大模型 API 厂商 (DeepSeek / OpenAI / Anthropic / 等)
* **依赖形态**：公有云标准化 HTTPS RESTful / SSE 流式接口。
* **上游地址**：各厂商官方 API Gateway。
* **风险评估**：公网网络波动、接口限流 (Rate Limit)、服务停机 (503/500)、计费消耗。
* **策略档位**：**C (接口隔离+可降级)**。
* **治理手段**：
  1. **任务感知动态路由**：TaskWeaver 自研模型路由层按任务类型（规划、编码、审查、极速响应）动态分发；
  2. **熔断与级联重试**：主选厂商超时或错误时，自动按权重降级至备份提供方；
  3. **离线与本地模型支持**：支持直连 Ollama 本地部署模型，完全隔绝外网依赖。

### 5. MCP 生态 (Model Context Protocol)
* **依赖形态**：基于 `@modelcontextprotocol/client` 标准库构建的客户端。
* **上游地址**：Anthropic 开源标准规范。
* **风险评估**：外部第三方 MCP 服务崩溃或响应延迟。
* **策略档位**：**C (接口隔离+可降级)**。
* **治理手段**：
  1. MCP 工具调用与系统原生核心工具（读写文件、执行终端、文本搜索）解耦；
  2. MCP 服务端异常时静默降级，不阻断主对话流。

### 6. Ripgrep 二进制
* **依赖形态**：原生跨平台可执行文件。
* **上游地址**：BurntSushi/ripgrep。
* **风险评估**：平台架构缺失（如特殊的 arm64/x64 二进制缺失）或系统执行权限限制。
* **策略档位**：**A (冻结内化)**。
* **治理手段**：
  1. 优先使用系统 PATH 或打包携带的静态二进制；
  2. 运行时具备降级探测：若二进制不可用，平滑回退到 Node.js 内存扫描方案。

### 7. 基础前端/桌面栈 (Electron, React, TypeScript 等)
* **依赖形态**：通用开源基础技术栈。
* **上游地址**：npm 官方镜像。
* **风险评估**：底层依赖 CVE 漏洞、Node/Electron 主版本升级不兼容。
* **策略档位**：**D (文档化接受)**。
* **治理手段**：严格使用 `package-lock.json` 锁定固定哈希与版本，定期运行依赖安全扫描。

## 三、上游断供应对表

当上述任一外部依赖发生断供（服务不可达、协议封禁、接口不兼容或证书过期）时，系统自动执行下述降级机制，并指引人工介入处置：

| 故障场景 (哪个断) | 表现特征 | 系统自动降级行为 | 人工处置动作 |
| :--- | :--- | :--- | :--- |
| **场景 1：OpenCodex 代理崩溃或端口冲突** | 10100 端口无响应，界面提示“代理未连接” | 1. 自动从可用模型池中剔除 `opencodex/*` 模型；<br>2. 任务路由自动切换至已配置的云端商业模型（DeepSeek / Claude 等）；<br>3. 前端 UI 弹出温和告警，保留当前对话线程。 | 1. 检查本地是否有残留的后台进程占用端口；<br>2. 在“模型设置”中点击「启动 OpenCodex」触发自动重启；<br>3. 或直接切换主力模型至 DeepSeek 等官方直连渠道。 |
| **场景 2：Cursor 逆向协议封禁或版本失效** | 请求返回 403 Forbidden、协议握手失败或持续空回复 | 1. 捕获协议异常并标记 Cursor 通道不可用；<br>2. 动态路由阻断发往 Cursor 的请求，重定向至用户设定的备份模型通道；<br>3. 保存当前会话上下文，防止数据丢失。 | 1. 在模型设置中将主力通道切为标准 OpenAI / DeepSeek API；<br>2. 运行 `scripts/check-ocx-upstream.mjs` 查看上游最新协议修复；<br>3. 审查 vendor 补丁并按需合入新版本。 |
| **场景 3：主要公有云模型厂商停机 (如 DeepSeek 宕机)** | API 返回 502/503 或长时间超时连接失败 | 1. 触发路由熔断器，自动切入备选 Provider（如 SiliconFlow 镜像、OpenAI 或 Claude）；<br>2. 记录错误日志，并向用户报告故障原因与切换目标模型。 | 1. 在模型设置面板确认备用模型提供商的 API Key 余额；<br>2. 若网络彻底断网，切换至本地 Ollama 离线模型。 |
| **场景 4：外部 MCP 插件进程崩溃或假死** | 工具调用等待超时，进程退出异常 | 1. 隔离故障 MCP Client，释放当前轮次的工具锁；<br>2. 标记该 MCP 工具离线，主 Agent 改用内置通用工具或向用户报告工具执行失败。 | 1. 在设置中关闭故障 MCP 插件；<br>2. 检查本地 MCP 服务的配置文件与依赖项。 |
| **场景 5：Ripgrep 原生程序被系统安全策略拦截** | 搜索文件返回 `permission denied` 或找不到可执行文件 | 1. 动态检测失败并自动激活 Node.js 内置正则表达式搜索备选实现；<br>2. 对搜索范围进行上限保护以避免内存溢出。 | 1. 检查 macOS 辅助权限或 Gatekeeper 拦截记录；<br>2. 确认系统具备可执行权限（`chmod +x`）。 |
| **场景 6：Z 运行时原生组件构建异常** | 启动时提示运行时版本不匹配或未初始化 | 1. 自动回退至预置的通用进程执行器；<br>2. 限制高阶沙箱隔离特性，保证基础会话与命令仍然可跑。 | 1. 运行 `npm run build:z-runtime` 重新编译本地运行时；<br>2. 运行 `npm run test:z-recovery` 执行自检。 |

## 四、服务条款 (ToS)、合规与隐私保护声明

### 1. 毕设与学术定位
本系统（TaskWeaver）为计算机科学与技术专业毕业设计研发成果，定位于**任务感知动态模型路由的多智能体协作编程桌面应用**。系统内的多渠道接入能力旨在验证多模型协同分工、容灾降级与性能对比。

### 2. 逆向协议通道使用界限 (OpenCodex / Cursor)
* **研发实验用途**：项目中集成的 OpenCodex 代理及 Cursor 协议解析能力，**仅供个人开发者在本地 Loopback (`127.0.0.1`) 环境下进行技术研究、协议对比与学术验证**；
* **用户自主授权**：所有涉及第三方平台的操作均须用户通过本地浏览器或官方 OAuth 完成登录，TaskWeaver 本身不包含任何绕过验证的破解代码；
* **风险自担原则**：第三方平台可能随时调整其服务条款 (Terms of Service)、速率限制或调用策略。使用相关逆向协议通道产生的一切调用限制、账号安全风险均由使用者自行承担。

### 3. 正式推荐路径
* TaskWeaver **官方正式推荐的主力通信路径为“官方 OAuth 直连授权”与“商业提供商标准 API Key”**（如 DeepSeek、Anthropic、OpenAI、OpenRouter 等）；
* 生产环境或正式演示时，建议优先使用官方商业接口，以保障最高的稳定性、可用性与服务条款合规性。

### 4. 隐私安全与数据保护
* **零私有数据窃取**：TaskWeaver **绝不读取、不嗅探、不上传**用户宿主环境中的私有敏感数据、密码、密钥或第三方软件的私有凭据；
* **凭据本地加密**：系统保存的所有 API Key 与认证 Token 均严格存储于用户本机本地安全存储中（或 OS Keyring），绝无任何外部回传行为；
* **透明可审计**：所有网络调用、工具执行日志与模型交互过程在桌面端完全可视、可审计、可断开。
