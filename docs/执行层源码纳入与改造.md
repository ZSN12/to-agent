# 执行层源码纳入与自适应改造（TaskWeaver）

## 目标

将 pi 相关**完整源码**放入毕设仓库 `packages/pi/`，在本地修改、构建后由 TaskWeaver 加载，实现：

- 不依赖从 npm registry 安装 `@earendil-works/pi-coding-agent`；
- 改造与毕设编排代码**同一仓库、同一迭代**；
- 对外产品仍通过 `TaskWeaver.app` 分发，用户无需单独安装 pi。

## 仓库布局

```text
毕设/
  electron/agent/agent-runtime.mjs   # 唯一入口，指向本地 coding-agent dist
  electron/backend/                  # TaskWeaver 自有：门控、DAG、模型分配、记忆…
  packages/pi/                       # pi monorepo 源码（纳入改造）
  vendor/runtime/                    # 可选：已编译快照，用于 seed-dist / 离线兜底
```

## 日常命令

| 命令 | 说明 |
|------|------|
| `npm run runtime:seed-dist` | 用 `vendor/runtime` 中已验证产物填充 `packages/pi` 各包 `dist/`（改源码前可先跑通） |
| `cd packages/pi && npm install && npm run build` | 从源码全量编译执行层 |
| `npm run test:all` | 验证 TaskWeaver 与执行层接线 |

## 与「完全不依赖外部」的边界

- **源码在仓库内**：是，改在 `packages/pi`。
- **运行时仍可调云端模型 API**：是（产品能力）；本地 Ollama 等为可选 provider。
- **第三方 npm 库**（React、Electron、厂商 SDK）：仍在 `packages/pi` 与根 `package.json` 的依赖树中；纳入源码 ≠ 重写全部依赖。

## 答辩建议表述

> TaskWeaver 将开源 Agent 运行时源码纳入 `packages/pi` 并针对桌面编排场景二次开发；**任务感知门控、DAG 调度、子任务模型路由与外置记忆**为本文实现与贡献重点。

详见 `packages/pi/TASKWEAVER.md`。
